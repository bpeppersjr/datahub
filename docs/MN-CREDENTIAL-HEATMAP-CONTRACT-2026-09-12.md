# Minnesota credential heatmap aggregate contract

This independent data-service slice adds no UI, endpoint, geography, publication, acquisition or cache. The existing retained credential panel already presents state/category percentages and reported-ZIP groups; its downstream-publication correction is implemented separately. A future Heatmap Builder mode should synchronize its category and reported-state selection with one alignment card, rather than duplicate that panel.

`buildMnCredentialHeatmap` requires the explicit reviewed registry selection and calls the existing bounded retained loader once per build (150 MB / 250,000-row limits, full release/row verification and before/after checks). Its immutable aggregate contains pins, not source rows. `aggregateMnCredentialHeatmap` provides structural validation for fixtures and cannot mint retained verification. `selectMnCredentialHeatmap` reuses only a same-process immutable built aggregate; it never reads source files or shrinks percentage denominators. There is no long-lived cache. The integrating caller owns explicit reuse, invalidation and recheck; pins describe the snapshot at build time, not perpetual currentness. A later metadata-only publication check cannot replace the initial full retained verification.

Aggregation keys are reported-state + reported-ZIP5 + credential category. Repeated credential identifiers remain separate source rows; duplicate reporting-row identities reject. ZIP4 is not aggregated. All 50 states and DC receive state observations; other/unresolved reported states remain in an explicit null-state bucket without exposing arbitrary source strings. Missing ZIP remains a null-ZIP group. No names, contacts, row identifiers, coordinates, county membership, inferred business counts or polygon membership escape the helper.

Accounting clarification: the published extension declares 11,456 credential rows and two rows without existing ZIP views, with one missing ZIP. The coverage extension tests null ZIP keys against the existing-view set, so these are potentially overlapping counters, not three excluded rows. This helper deliberately does not open the large ZIP view or infer its membership: `rowsWithoutExistingZipView` is null and `existingZipViewMembership` is not-evaluated. Every accepted row remains in its postal group regardless of existing coverage-view membership. A ZIP code such as an unmatched code is still visible; missing ZIP is also visible. No absent geometry can silently remove either from totals.

Smallest subsequent visualization: state choropleth labeled reported-address state plus non-geographic reported-ZIP heat tiles for the selected state. Joining validated state labels to separately verified state geometry is an integration step, not performed here. State -> county -> ZCTA business navigation must not be reused. Reported ZIP groups are not governed ZCTA membership; geographic ZIP polygons require a separately reviewed visualization contract. Business `all` totals, peer-business alignment, physical-location drilldown and demographic filters remain outside this mode.

Claims remain local-review-only, public export false, geographic assignment false, unknown business/site/completeness counts, and historical source integration false. Downstream publication is a separate proof, not asserted by this aggregate. Source observation time is distinct from reporting creation time.

Validation boundary: focused fixtures only initially; no native retained build, source request, download, large ZIP replay, full application check or runtime launch is part of this slice. Root review precedes any optional actual retained verification. Independent integration tests should preserve business totals and suppress county navigation/business tooltips in credential mode.

Focused evidence: eight tests passed (cross-state same ZIP, repeated credentials, missing/unrepresented postal groups, fixed filter denominators, zero observations, invalid/duplicate input, outside-state conservation, preflight and mid-build cancellation, and inherited array-iterator rejection); ESLint passed on both owned modules. No fixture result asserts native source verification. The helper's non-disjoint missing-ZIP counter is metadata, not an additional group to sum. Unknown existing-ZIP membership stays unknown even for a code that looks unusual.
