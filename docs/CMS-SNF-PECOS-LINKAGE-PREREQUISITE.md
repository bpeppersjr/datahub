Dictionary-backed types: `ENROLLMENT ID` is a 15-character alphanumeric application identifier; `ASSOCIATE ID` and `ASSOCIATE ID - OWNER` are 10-character numeric PAC identifiers. PAC can span enrollments. `NPI` is a 10-character numeric NPPES identifier; `MULTIPLE NPI FLAG` is Y/N. `CCN` has CHAR(15) storage, despite guidance's six-character certification description. Preserve all as strings with leading zeros; do not truncate or pad to force a match. Incorporation date is not enrollment activation. API DATE versus dictionary NUM(8) requires observed date-format conformance before conversion.

Owner fields selected for a proposed organization-only layer: `ENROLLMENT ID`, `ASSOCIATE ID`, `ASSOCIATE ID - OWNER`, `TYPE - OWNER`, `ROLE CODE - OWNER`, `ROLE TEXT - OWNER`, `ASSOCIATION DATE - OWNER`, `ORGANIZATION NAME - OWNER`, `DOING BUSINESS AS NAME - OWNER`, `PERCENTAGE OWNERSHIP`, `PARENT COMPANY - OWNER`, `OWNED BY ANOTHER ORG OR IND - OWNER`. Owner type is I/O. Parent-company is a reported Y/N/blank flag, not a verified hierarchy. Some organization flags permit Y/blank only, unlike Y/N/blank flags: blanks never mean false. Keep exact role codes; the dictionary includes 01, 03, 25, 34-44, 63, 71, 72, 84-86. Ownership/control roles are not interchangeable, and percentages must not be summed into a forced 100 percent.

Guidance defines the universe as approved-to-bill enrollments at the PECOS snapshot, with possible data-quality omissions, not independently operating facilities. Enrollment is unique by enrollment ID; owner and additional-NPI relations join on that key. Additional-NPI layout is exactly two documented columns, `ENROLLMENT ID` and `NPI`; the base file contains one prioritized NPI. Ownership is self-reported and includes managerial control. The guidance warns that ultimate-parent identification and comprehensive historical enrollment are unavailable. Retain any newer parent flag as a dated assertion rather than overriding that boundary. Affiliations can be missing or lag ownership changes.

## Proposed connector contract, not yet implemented

Implement separately as `runner/cms-snf-pecos-prerequisite.mjs`, its fixture test, and `config/source-policies/cms-snf-pecos.json`; later add a standalone acquisition lifecycle only after the distribution gate above. Reuse bounded file/receipt/lease patterns from nursing acquisition without editing its pinned implementation, recovery or selected rows. No registry, production or map adoption in this slice.

- Directory edge: exact raw CCN equality only, typed `cms-certification-number`, linked to fixed recovery/source-row identity. Represent zero, one or multiple enrollment matches; preserve unmatched directory rows and PECOS-only rows. No name/address fuzzy fallback. Lexically incompatible CCNs stay unresolved. Repeated CCNs do not collapse applications.
- Enrollment edge: immutable release + source-row identity, enrollment ID, provider PAC and all separately sourced NPIs. Cross-check provider PAC on owner rows against enrollment, retaining discrepancies for inspection. Owner relation identity includes source row; never assume enrollment/owner pair alone is unique, since roles/dates may repeat. Report duplicate relations rather than deleting evidence.
- Organization-owner projection admits only `TYPE - OWNER = O`; count individual and unknown-type exclusions independently. Personal names/titles and all owner addresses stay outside the selected layer. Raw source remains internal and access-controlled; selected organization relationships are local-review-only. No public export by this prerequisite.
- Keep reference month, retrieval clock, dictionary version and raw association/incorporation date independently. The August 2026 directory must not be relabeled May 2026 PECOS-current. `currentOperationsVerified:false`; business/site/canonical-owner counts remain null. Keep directory chain ID and PECOS affiliation ID in separate typed namespaces; no equality or parent/network inference merely from matching digits.
- Conservation outputs: directory rows = linked + unlinked, separately count multi-enrollment directory rows; enrollment rows = unique + duplicate/error bucket under explicit validation; owner rows = organization + individual + unknown-type; selected relation counts retain duplicates and invalid/missing optional values. Report missing additional-NPI resource or Y-flag mismatch as incomplete NPI coverage, not a guessed unique NPI.

Proposed conservative resource policy: one national release only, single physical shared CMS exclusive lease (the existing hospital/nursing lock), sequential requests, no redirects/retries or credentials. Metadata max 2 MiB each, documents max 5 MiB each; candidate CSV ceilings 32 MiB enrollments, 256 MiB owners, 16 MiB additional NPIs, total 340 MiB / 20 requests / 600 seconds; 30-second metadata/document and 180-second data request ceilings, 1-second cleanup. These are app ceilings, **not published CMS rate limits or verified release sizes**; exceeding them fails for review, never silently expands. Prefer one pinned distribution per file to large API page replay. Durable request intent and manifest-last publication, bounded streaming CSV/UTF-8, cancellation, complete raw failure retention and unknown-transport lease quarantine follow reviewed acquisition patterns.

Before acquisition, the source policy must preserve CMS attribution, government-endorsement prohibition and any dataset-specific notice exception; replay the retained CMS reuse notice if adopted, rather than assuming a FAQ URL is immutable. Public-use discovery supports no credential gate. Source row counts, exact CSV headers/date formats, extra-NPI distribution, real join cardinalities and snapshot alignment are still unverified. No completeness or native-ready claim follows from this audit.
