## Assessment observation and coverage applicability (report schema 3)

Schema 3 separates the historical source observation from the coverage release to which that observation can be applied. `assessmentObservation` preserves the original `observedAt` and reports `not-evaluated-no-age-policy`; publishing or replaying a coverage release is never treated as a new source observation. `assessmentCoverageApplicability` is independently `exact-pin`, `reviewed-compatible`, `not-reviewed`, `missing-coverage-release-id`, or `unassessed`.

`reviewed-compatible` is available only when the immutable, hash-verified offline reassessment chain starts at the assessment's pinned release, reaches the current coverage release, and includes that jurisdiction. Missing jurisdictions and unknown transitions fail closed as `not-reviewed`; changed reassessment evidence is rejected. The legacy exact-match and `assessmentFreshness` fields remain for compatibility and provenance, but their `stale` value means only that release IDs differ. It does not mean a source was re-observed or that a dated assessment is unusable.

State-access report schema 2 makes source-assessment age explicit. The governed coverage release remains the sole release used for the four access categories: `direct-state-publisher`, `national-dataset-state-evidence`, `unsupported-missing`, and `unsupported-evidence-not-measured`. Assessment holds are context only and cannot change those categories.

Every jurisdiction now has an `assessmentContext.status` of `current`, `stale`, `missing-coverage-release-id`, or `unassessed`. Each hold evidence item is labeled `current-state-publisher-assessment-hold` or `historical-state-publisher-assessment-hold`, carries both the assessment and current coverage release IDs, and declares `evidenceClass: assessment-context-not-coverage-evidence`. The report-level `evidence.assessmentFreshness` and `summary.assessmentFreshnessStatusCounts` quantify the mismatch across all 51 jurisdictions. An absent assessment release ID is never treated as a match.

At the time this change was prepared, the latest retained schema-1 report compared current coverage `national-business-coverage-views-20260911-040908332Z-f01c882a` with assessment coverage `national-business-coverage-views-20260902-115337634Z-ba689784`. Those identifiers differ. The new report contract therefore classifies catalog assessments pinned to the latter release as stale; it does not refresh them, fabricate coverage, or change a production pointer.

Each state has one flat peer-workstream template in `config/state-access-workstreams.json`. A configured peer name is not a live agent. `IN_PROGRESS` appears only when a caller explicitly supplies that state as an operator-reported assignment. The configured concurrency of four is total agent capacity, not four available state workers. Available capacity remains unknown unless the caller supplies an observed total covering all active work, including the coordinator and unrelated rebuild work.

## Application handoff

The handoff ends agent ownership of routine acquisition execution: validate the source and connector prerequisites, submit the scoped work through Co*Tive's managed collection path, and record the accepted operation ID and persisted receipt. Then move the state agent to another validation or connector task. Do not reserve agent capacity or continuously poll with Codex while bytes download. The application owns execution and its implemented resource limits, progress, cancellation, and failure handling; the application service must remain running. Failed or ambiguous operations that the scheduler pauses require inspection rather than an assumed automatic retry.

Existing verified releases are inputs to local processing and promotion, not a reason to acquire the same bytes again. Check retained inputs before dispatch. This is an operating requirement, not a claim that the scheduler already implements general freshness-based reuse. Application job submission and production promotion remain separate, independently evidenced steps.

Each state/industry cell lists applicable configured source IDs, prerequisite path presence, known source limitations, and `acquisitionExecutor: cotive-app`. Published state evidence plus present prerequisite paths yields `APP_PREFLIGHT_REQUIRED`, meaning only that the job is eligible to be submitted for application validation. Path presence does not validate prerequisite contents. `prerequisiteContentsValidated` and `jobSubmitted` remain false because this report neither validates content nor submits jobs. `recurringSchedulerImplemented` is now null with `schedulerObservation: not-inspected-by-ledger`: scheduling exists in the app, but this source ledger does not inspect scheduler availability, enabled schedules, or actual dispatch. Consumers must preserve null as unknown, not convert it to false. Older immutable reports retain their obsolete false value and are not current scheduler-capability evidence. State agents validate evidence and connectors, then hand eligible work to the governed application queue. They should not remain occupied monitoring downloads.

Run `node scripts/report-state-access.mjs`. Optional `--active-state AL` values record operator-reported state assignments. `--observed-total-active-agents N` may be supplied only when the total across all work is actually known. Reports are immutable and a collision fails instead of overwriting.
