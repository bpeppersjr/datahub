## Executed contract

Version 1.1.0's eighteen-request sequence checks server ownership, layer metadata, the owning portal's service item, the separate public ArcGIS layer item, layer iteminfo, the disclaimer page item and content, layer XML and the selected count, then repeats them in reverse. Version 1.0.0's original ten-observation receipts remain verifiable with their original, narrower evidence claims. Requests are serial, spaced one second apart, capped at 128 KiB per response and a 15-second per-attempt deadline including body consumption. At most three attempts are allowed for transient network/deadline failures and HTTP 429/5xx. Publisher Retry-After is honored; waits over one minute defer rather than being shortened. Cancellation interrupts requests, body reads and pacing. Redirects, ArcGIS errors, facility/ID payloads, invalid UTF-8, oversized bodies and malformed envelopes fail closed.

The contract pins both item roles, the public service/layer URLs, all 23 declared field names/types/lengths/domains, query capabilities, the OID and native Web Mercator CRS. It defines an explicit 12-field future business/address allowlist excluding contact names/telephone. `CategoryType='LICENSED GROUP'` is fixed. Counts may change between preflights; zero or more than 50,000 requires review. Changed retained metadata or counts within one preflight are rejected. This is a paired observation check, not proof of a transactional snapshot.

Selected public JSON metadata, complete returned item/iteminfo `licenseInfo` strings, all disclaimer page markdown cards and exact layer XML bytes are retained. These are not complete raw JSON or HTML response bodies. Unknown disclaimer component types fail closed rather than being omitted. Private service addresses and token-generation routes are neither retained nor followed. XML validation covers fatal UTF-8, envelope, forbidden declarations, source/CRS/notice markers and hashes, not full XML parser wellformedness or schema validation. XML is never rendered or evaluated. The receipt is reconstructible from its hashed observations; output claims cannot be changed independently. Receipt publication uses fsynced exclusive temporary files and non-overwriting hard-link publication, with canonical-path and ownership checks. Tests use separate `data/tmp` directories, not the live source receipt folder.

## Coordinate acquisition contract

Request geometry with `outSR=4326`, `returnGeometry=true`, `returnZ=false` and `returnM=false`, retaining the existing attribute allowlist (not the separate Latitude/Longitude attributes). Omit generalization, quantization and precision-rounding parameters. Esri documents [outSR and datum transformation](https://developers.arcgis.com/rest/services-reference/enterprise/query-map-service-layer/) as geometry controls; do not invent a source transformation from the map extent alone.

Before normalization, require response point geometry and explicit `spatialReference.wkid=4326`; optional latestWKID and per-feature CRS must agree. Map x to longitude and y to latitude using strict finite numeric checks and geographic bounds. Missing/null or documented empty points remain nullable coordinate pairs with explicit reasons; malformed partial points must not become valid coordinates. [Esri's geometry reference](https://developers.arcgis.com/rest/services-reference/enterprise/geometry-objects/) documents empty points; zero is not its missing-point sentinel. Flag `(0,0)` and other Wisconsin-location anomalies without discarding the entity or inventing a replacement. Retain raw evidence and distinguish geographic plausibility from verified boundary/address accuracy. Do not derive source ZIP, county or address from these points. This is a reviewed implementation contract, not an already-built acquisition/normalization module.
