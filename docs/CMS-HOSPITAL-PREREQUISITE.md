# CMS hospital prerequisite implementation

Two-stage offline development slice, not a live connector. No source calls, live CSV, query API, schedule, global registry, UI or output artifacts are introduced.

1. `inspectCmsHospitalMetadata(Buffer, {observedAt, signal?})` validates bounded fatal-UTF8 metadata bytes against the documented CMS dataset/title/publisher/public access, canonical CMS distribution path and dictionary URL, and separate valid issued/modified/released dates. It records a SHA-256 and immutable same-process snapshot. Caller-supplied metadata is not authenticated transport evidence. The exported request contract fixes the metadata URL, GET, one concurrent request, no redirects, and internal byte/time caps; this module never executes it.
2. `inspectCmsHospitalCsvForConformance(Buffer, metadataSnapshot, {signal?})` parses bounded caller-supplied CSV with BOM/quoting support, hashes the exact bytes and produces an immutable selected-field fixture projection. It requires only the ten documented selected headers, in any order. It neither fabricates the remaining headers nor asserts the advertised 38-column order. Duplicate headers, missing selected headers, inconsistent rows, invalid IDs and duplicate facility IDs reject the entire conformance, without partial publication. Duplicate-ID policy must be revisited if actual source evidence establishes a valid one-to-many relationship; never silently deduplicate.

Selected source fields: facility ID/name, address, city, state, postal code, county label, hospital type, ownership category and emergency-services value. Telephone and rating/quality columns are deliberately excluded; extra columns are parsed only to preserve row alignment and never projected. Source ID remains a six-character string including leading zeros, provisionally typed as CMS PDC facility ID, not NPI/CCN/organization/campus equivalence. Type, ownership and emergency values are preserved, not interpreted as parent company or current operations. Separate raw postal, ZIP5 and ZIP4 fields preserve recognized five-/nine-digit forms; absent/unknown formats stay nullable and USPS-unverified. No points or governed membership are inferred.

Bounds are internal controls, not measured source limits: metadata 1 MiB; CSV 20 MiB, 25,000 data rows, 100 headers, 65,536-character parser record cap, plus smaller selected-field limits. Cancellation checks run during input decoding, parsing and batching. Since the prerequisite writes nothing, failures have no published artifacts to clean up. Metadata/CSV hashes provide replayable byte identity only; they do not authenticate the supplied bytes or grant acquisition/publication authority.

Policy contract: `config/source-policies/cms-hospital-general-information.json`, version 1.0.0, offline-prerequisite-only. CMS's government-data reuse notice supports later reviewed use with attribution and no endorsement, but this slice has `acquisition_authorized:false`, `connector_ready:false`, public export false and local-review-only fixture output. Source title/dictionary observations are documented separately in the September 12 source-contract note. No private records or credentials belong in fixtures.
