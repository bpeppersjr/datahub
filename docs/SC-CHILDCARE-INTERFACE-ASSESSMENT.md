# South Carolina childcare interface assessment

The separate `sc-childcare-interface-assessment` connector inspects exactly two fixed public resources: the [provider search page](https://scchildcare.org/provider-search/) and its [publisher static search script](https://scchildcare.org/js/providerSearch.js?v=2). The downloaded script is treated as text. No browser, search submission, `all=1` query, export, provider detail request, account action or contact is involved.

The October 7 manual-export discovery remains historical evidence. The fixed page and script expose the advanced-search form and search routes but do not expose an Excel delivery contract, columns, row limit, provider type vocabulary or snapshot date. Absence of export or paging keywords in these two resources cannot establish that a human-operated results view lacks an Excel control. Static search input names are never interpreted as workbook headers or a verified provider schema.

Independent source inspection found that the script routes a blank/All search to `/provider-search/?all=1`. This is a provider search, so it must never be used as a zero-row metadata probe. Neither discovered query route was executed. The historical Excel control was not reproduced in the two static resources; this assessment makes no claim that the publisher removed it. The complete disclaimer, privacy and usage notices remain unresolved.

Run `node scripts/preflight-sc-childcare-interface.mjs` for an explicit assessment. It makes at most two sequential requests, rejects redirects and alternative URLs, caps each response at 131,072 bytes, uses one 30-second deadline and performs no retries. The receipt retains only exact recognized interface markers and response hashes/byte counts. Raw HTML and JavaScript are not written to disk; provider rows and contacts are not parsed or retained. Errors are generic and exclude response contents. Cancellation aborts pending requests and reads, including a transport which ignores its abort signal.

The immutable receipt is published below `data/business-sources/sc-childcare/interface-assessments/` using exclusive temporary creation, owned-file verification and non-overwriting publication. Its verifier checks an exact expected relative path, SHA-256 and byte count, closed receipt shape, fixed request roster, current configuration hashes and conservative claims. Input/output aliases, paths outside datahub, hard links and manifest-bearing output directories are rejected. A receipt is assessment evidence only; it creates no business release, current pointer, app acquisition job, production enrollment, periodic refresh or industry count.

Ten gates remain unresolved: actual human-inspected export delivery/schema; row limit/selection scope; automated bulk access; provider cohort separation; residential home privacy; publisher snapshot/status semantics; row/provider-number conservation; separate ZIP5 and ZIP+4 fields; applicable usage/reuse notices; and production admission. No ZIP or geocode completeness requirement is added to map reporting. Source-listed licensing, approval, registration, exemption and operation remain distinct. No provider export is authorized by this assessment.
