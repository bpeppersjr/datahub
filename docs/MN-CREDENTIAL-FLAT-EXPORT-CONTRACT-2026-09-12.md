## Implemented interface and fixture evidence

`exportMnCredentialFlat({selection:'config/mn-credential-registry-selection.json',policyMode:'local-review-only',format:'csv'|'jsonl'|'both',fields?,states?,signal?})` is the native service API. Optional fields use the exported closed `MN_CREDENTIAL_FLAT_FIELDS` allowlist; mandatory identity, typed credential, reported-state, provenance and restriction fields in `MN_CREDENTIAL_FLAT_REQUIRED_FIELDS` are always retained. Omitted fields select every allowed field; an empty list selects mandatory fields only. State filters accept distinct uppercase 50-state/D.C. codes and use the source's reported address state, never the publisher jurisdiction. Omitted/empty states select the entire reviewed cohort.

The CLI is `node scripts/export-mn-credentials.mjs --selection config/mn-credential-registry-selection.json --policy-mode local-review-only --format both`, with optional repeated `--field FIELD` and `--state STATE`. This command has not been run against native data in this slice. It honors shared signal/IPC cancellation and emits a bounded recovery descriptor if publication becomes uncertain. Native output remains under `data/exports/mn-credentials/<run-id>`; synthetic output is confined to `data/tmp/mn-credential-flat-tests/<run-id>`.

`source_credential_rows`, `filtered_out_credential_rows` and `credential_rows_written` remain separate in descriptors/manifests. Filtering does not weaken full-source validation. Zero-row filtered output is valid: CSV contains its header and JSONL is empty, with explicit zero counts and retained source provenance. Public policy and unsupported fields/states/selections fail before native retained loading. The exporter revalidates the full selected input before publication; `verifyMnCredentialFlat(manifest,expectedHash,{signal})` independently loads the reviewed input and verifies exported rows, fields, filters, claims, hashes and roster. Verification is an offline retained-source operation, not a new source request.

The existing normalized/reporting contract rejects U+0000–001F and U+007F in source text, including embedded LF/CR. CSV therefore verifies physical records under that source contract; multiline source text is explicitly rejected in tests, not silently flattened. Quoted commas/quotes remain governed by CSV parsing, and JSONL preserves original formula-like text while CSV applies the declared presentation escape.

CSV consumers must import ZIP and credential-identifier columns as text. Quoting preserves the file bytes but does not prevent Excel or another spreadsheet app from automatically converting numeric-looking strings and dropping leading zeros. JSONL preserves string types directly. The exporter does not claim that double-clicking a CSV in a spreadsheet preserves those types.

Twelve focused fixture tests passed with zero failures; targeted ESLint passed. The suite includes closed field/state selection, mandatory provenance, WI-reported versus MN-publisher semantics, valid zero-row exports, explicit multiline rejection, repeated credentials, typed dates/postal fields, CSV safety, rehashed tamper, cancellation before/after publication, recovery references and changed hard-link ownership preservation. Selection arrays must be dense own-data arrays with no accessors or extra properties; field count is bounded to the allowlist length and state count to 51. Sparse-array and malformed-selection regressions pass before any retained load. Root and an independent read-only reviewer found no blocking defect in the selected-field/state/count implementation. The native hold was subsequently released for exactly the retained-only validation below; application launch, source calls, full check, UI and managed-operation integration remain outside this slice.
