# National goal-completion matrix

`npm run goal-completion:build` creates an immutable local report beneath `data/national-goal-completion-matrix/releases/<release-id>`. It reads the current retained coverage pointer, its pinned state/source aggregates, the governed national reporting catalog and the retained IRS state summary. It performs no provider request, source download, production reconciliation, approval, current-pointer update or stale-assessment rewrite.

The report contains exactly the 50 states and District of Columbia crossed with the seven categories declared by the eight-source national reporting denominator plus a `general-business` goal category requiring one broad jurisdiction organization layer. Broad-layer contract 1.1 recognizes nine exact retained state layers—AK, CO, CT, DE, FL, IA, NY, OR, and PA—while preserving all-business completion as unknown. Every category cell includes its governed datasets, state record availability, retained-reporting authorization basis, source and coverage release evidence, current temporal review status, ZIP contribution, geocode rate and an explicit gap reason. `dataset_availability` distinguishes measured members (`available` or `observed-zero`) from `unmeasured` members. Its percentage is the available share among measured members; `denominator` remains the full declared category size and `measured`/`unmeasured` counts are explicit. If no member is measured, the percentage is `null` rather than 0%. An observed zero is measured evidence and contributes zero available. These values are not percentages of businesses, industry establishments, ZIPs or source completeness. Every jurisdiction and category therefore retains `all_business_completion_percent: null`.

Schema `national-goal-completion-matrix@1.1.0` adds the measured/unmeasured counts and status. For current-schema releases, the verifier requires manifest/report `created_at` equality and exact manifest/report evidence equality, then independently rebuilds the matrix with the report's retained `created_at` and `release_id`. Evidence changes in the currently retained authorized inputs produce a rebuild-required failure; unchanged evidence with different report semantics produces a tamper failure. The verifier retains explicit structural `@1.0.0` compatibility rules because those legacy manifests predate replay provenance. The view normalizes verified legacy cells from retained per-dataset statuses before display. No historical release is rewritten or silently substituted.

The builder now recognizes the existing all-or-nothing `national-reporting-ten@1.0.0` production enrollment. Only an explicit `production-enrollment-absent` result preserves the verified eight-source denominator. Unreadable, invalid, stale or partial enrollment evidence fails closed instead of silently substituting eight-source results, and the builder never adds only one CMS directory. A valid enrollment must independently bind the current coverage pointer and manifest, the successful eight-stage production receipt, the predecessor catalog, and both typed CMS coverage declarations. Only then does the matrix use ten governed sources and add CMS hospitals and CMS nursing homes together under `health-care` for all 51 jurisdictions.

CMS values remain publisher directory rows. Their state counts, fixed directory denominators, source manifests, enrollment hash, coverage hash and production-receipt hash are retained. Business, physical-site, current-operation and national-completeness counts remain null. The matrix claims no CMS county allocation or geocoding, and does not turn the separately retained ZIP reporting into a ZIP completeness claim. Both record-level policies remain `local-review-only`.

Authorization means only that a dataset is enrolled for retained reporting under the governed catalog and its declared export policy. The matrix does not infer permission for a new acquisition or broader redistribution. ZIP and geocode metrics are labeled source-release-wide because current retained aggregates do not support truthful per-state versions of those measures.

Publication writes `report.json` and then `manifest.json` into a new exclusive release directory. It intentionally creates no `current.json`; choosing a report for app-wide display remains a separate reviewed binding. The verifier rechecks the report hash, fixed 51-jurisdiction shape, dataset availability counts/measurement status/percent arithmetic, null completeness claims, zero-network declaration and no-production-pointer declaration. Its replay uses only retained readers and performs no writes or network requests. The eight-source and all-or-nothing ten-source boundaries are replayed through the same builder; replay never grants enrollment or treats either CMS directory independently.

Native release identifiers and hashes are emitted by the CLI after independent verification. Each release is local derived evidence, not a production dataset or approval.

## Management view

The authenticated read-only route `GET /api/business-map/goal-completion` scans the immutable release directory and verifies the newest versioned release directly; it does not use or create a mutable pointer. Optional closed `state` and `category` query values select detail while retaining all 51 jurisdiction cells for the category. If the newest release is corrupt or its retained inputs have drifted, the reader fails closed rather than silently substituting an older report.

Heatmap Builder shows this evidence in its existing right-hand summary. It reports available and unmeasured dataset counts separately, broad state-layer gaps, source freshness, authorization state and geocode context. An all-unmeasured category displays “Unmeasured” instead of 0%; an observed-zero category remains measured at 0%. “All-business completion” remains **Unknown** because no authoritative all-business denominator exists. Dataset-availability percentages must not be presented as the percentage of U.S. businesses collected.
