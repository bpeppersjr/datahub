# Maine ASC metadata preflight implementation

This bounded native implementation is a metadata prerequisite, not a business collector or an acquisition-ready connector. Its observed source contract is [the September 12 discovery record](ME-MEDICAL-PROVIDER-CONTRACT-2026-09-12.md). Development verification uses synthetic transports and an offline Chromium document parser only. No native Maine source session was executed for this implementation.

`node scripts/preflight-me-asc.mjs` is the native CLI. It accepts no endpoint, transport, or source configuration overrides. Standalone execution accepts no arguments; managed execution accepts only paired `--output` and `--operation-id`, strictly bound to an application operation before source access. Running it contacts Maine; do not use it as an offline test command. Exit 0 means an HTML export schema was observed with matching counts, 2 means inspection is required, and 1 means execution or publication failed. Neither 0 nor 2 establishes provider identity, row conservation, source completeness, collection permission, or current operations. Managed registration is now implemented; an appropriately authorized native validation and its persisted operation receipt remain outstanding.

The contract version is `me-asc-source-preflight@1.0.0`. Configuration is fixed to `https://gateway.maine.gov/dhhs-apps/aspen/`, category 12, and the observed county roster. The internal source policy is checked against a pinned SHA-256 of its parsed JSON serialization before any browser/source access and again before publication. Changing terms requires deliberate review and a new policy pin. The output schema is validated by the independent receipt reader. There are no named secret references, produced entities, identifiers, external artifacts, schedules, retries, checkpoints, or automatic recovery; cookies and CSRF fields exist only within the transient session.

The lifecycle is policy preflight, isolated offline-parser setup, sequential native session, metadata validation, parser/body/session cleanup, receipt publication, and independent verification. Resource class is one local browser and one sequential HTTP request. The budget key is Maine gateway public-provider metadata. Limits are 10 requests, 1 MiB per decoded response, 10 MiB total, 30 seconds per request, 330 seconds per session, at least 250 ms between request starts, and 1,000 provider selections. The fixed observed route normally requires six requests. Only the category-to-county redirect is allowed; external, alternate path, query, fragment, and repeated redirects fail closed. There are no retries or bulk provider acquisition.

Successful named form controls reproduce the county/list/detail/export flow, including rotating CSRF tokens, hidden list `referer`, repeated `which`, the chosen `details` submitter, and empty export POST. Unnamed submit buttons and unchecked towns are omitted. The browser disables JavaScript and service workers, blocks network requests, and uses a run-scoped profile/artifacts directory under local `data/tmp`; it closes and removes scratch before cleanup can be verified. Body cancellation has a bounded cleanup wait. Outstanding/noncooperative transport or failed parser/body cleanup prevents receipt publication.

Receipts retain only fixed claims, limits, status, timestamps, allowlisted labels and form names, structural counts/hashes, response byte counts/hashes, and count comparisons. Unknown headers are counted without retaining text; unsupported export formats remain unresolved. Dynamic body hashes are observation fingerprints, not version pins or replayable evidence. Matching selection/detail-label/export-table counts does not prove that the same records were conserved, so `conservation_verified` remains false.

The CLI uses the shared cancellation helper for SIGINT, SIGTERM, and app IPC `{type:'cancel'}` messages. The receipt writer requires an unchanged result issued by the session module. Synthetic results can only publish beneath `data/tmp/me-asc-receipts`; native results use `data/business-sources/me-asc/preflights`. It writes a run-scoped `receipt.json`, rereads and hashes it, and atomically publishes `manifest.json` last. The independent reader enforces exact filenames, bounded single-link reads, hashes, fixed metadata schema and claims, then rehashes the manifest. Schema-observed receipts additionally require the exact five-step direct or six-step redirected itinerary, successful statuses, required page/form metadata, and consistent counts. These checks establish local integrity, not independent authentication of a native publisher response. Failed unpublished writes remove owned files; uncertain published output is preserved for inspection.

The managed handoff uses the existing source-prerequisite endpoint with exactly `{sourceId:'me-asc-preflight'}`. It publishes native bundles beneath the operation's `output/jobs/<run-id>/`, binds the operation ID inside the manifest, and returns a fixed descriptor. The manager independently validates operation/run/path/hash/start-time/native-mode bindings and retained metadata even with an injected executor. Uncertain publication returns a bounded recovery descriptor; cancellation, recovery, nonzero exits and unresolved metadata remain inspection-required. Collection, acquisition, conservation, export permission and completeness flags remain false from the queued state onward, and no artifacts are exposed for download. Registration does not dispatch a session, enroll a collector or create dependent acquisition work.

The managed implementation's focused regression passed 29/29 tests covering Maine standalone and managed preflight, Oklahoma prerequisite compatibility, prerequisite gates and shared CLI cancellation. Owned-file ESLint and diff checks passed; test scratch directories were empty. All source-session tests used injected transport or offline parsing; managed native-shaped receipts were explicitly fabricated structural fixtures, not native acquisition evidence. No native Maine request, application launch, dependency installation or full repository check was performed in this slice. The exact source limits remain 10 requests, 1 MiB per response, 10 MiB total, 30 seconds per request, 330 seconds per session, 250 ms spacing and 1,000 selections; the manager reuses its existing 75-second cancellation grace period.

Focused verification uses the Maine tests plus `runner/managed-me-asc-prerequisite.test.mjs`, `runner/managed-ok-schema-prerequisite.test.mjs`, `runner/managed-source-prerequisite-gates.test.mjs` and `runner/cli-cancellation.test.mjs`. Set `ME_ASC_TEST_BROWSER_ROOT` only when tests need an existing approved local browser installation; scratch still remains in this checkout. The integrator owns final repository validation and the commit. Rollback of the managed slice removes the Maine catalog/dispatch/verifier registration and restores standalone receipt/CLI behavior; it does not delete retained evidence. The original standalone implementation can be rolled back separately if required.
