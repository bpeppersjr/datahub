# Utah Business List offline contract

This bounded connector implements the schema published by Utah's [Business List Service](https://secure.utah.gov/datarequest/businesses/index.html) and its [three-sheet example](https://secure.utah.gov/datarequest/businesses/listExample.html). Observed October 3, 2026, a full list costs $0.01 per record and is updated through the previous Tuesday. The [service landing page](https://secure.utah.gov/datarequest/index.html) limits full lists to subscribers; [registration costs $125 annually](https://www.utah.gov/subscription/) and [requires an account and Network Registration Agreement acceptance](https://www.utah.gov/subscription/faq.html). Customized lists cost $5 for the first 200 records, then $0.05 per additional record. This implementation authorizes none of those actions. See the [current reassessment](states/UT-BUSINESS-SOURCE-REASSESSMENT-2026-10-03.md).

Only an operator-supplied closed package beneath `data/imports/utah-business-list/packages/` is accepted. It must retain the original delivered workbook and separately contain three operator-derived JSONL exports. The validator pins the workbook and derived files by exact filenames, hashes, byte sizes, row counts, transformation declaration, and cross-sheet Entity ID references. It does not parse the workbook or prove the derived rows can be reproduced from it. Accordingly, output says `operator-derived-jsonl`, `source_native: false`, `source_authenticity_verified: false`, `reproducible_extraction_verified: false`, and `admission_eligible: false`. It performs zero network requests and writes no release, current pointer, or national admission.

The normalized result is provisional organization-level registration evidence from the operator-derived `BUSENTITY` export. It excludes Applicant Name and does not emit `BUSINFO` or `PRINCIPAL`, because those sheets can contain officers, principals, partners, registered agents, and other natural-person information. Source address and status are explicitly administrative registration evidence, not proof of a physical site or current business operation. ZIP5 and ZIP4 remain separate. No output may be admitted until an independent original-byte authenticity check and a deterministic workbook-to-JSONL replay establish equivalence.

## Standalone offline app operation

`node scripts/run-utah-business-list-app.mjs --selection data/imports/utah-business-list/packages/<package-id>/selection.json` creates a UUID-scoped operation. The operation durably records its start before copying inputs, validates snapshot hashes, writes and verifies a local-review-only release, removes its temporary snapshot, and finishes with a terminal receipt. Failure and cooperative cancellation remove only the operation-owned snapshot and unpublished release. Package inputs are never changed.

`node scripts/verify-utah-business-list-app.mjs --receipt data/imports/utah-business-list/operations/<run-id>/receipt.json` independently replays the receipt, start hash, manifest, record artifact, counts, input bindings, and authority claims. The managed server and Data Operations UI can dispatch this same local worker through `ut-business-list` after an operator selects a package. Managed completion independently verifies its receipt. Neither route can purchase, create an account, access the source network, update a current pointer, or perform national admission. Every release preserves `source_native: false`, `source_authenticity_verified: false`, `reproducible_extraction_verified: false`, and `admission_eligible: false`. Enrollment alone proves no successful operation; the package and operation directories were empty during the October 3 reassessment.
