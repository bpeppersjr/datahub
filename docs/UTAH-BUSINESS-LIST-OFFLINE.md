# Utah Business List offline contract

This bounded connector implements the schema published by Utah's [Business List Service](https://secure.utah.gov/datarequest/businesses/index.html) and its [three-sheet example](https://secure.utah.gov/datarequest/businesses/listExample.html). Observed October 3, 2026, a full list costs $0.01 per record and is updated through the previous Tuesday. The [service landing page](https://secure.utah.gov/datarequest/index.html) limits full lists to subscribers; [registration costs $125 annually](https://www.utah.gov/subscription/) and [requires an account and Network Registration Agreement acceptance](https://www.utah.gov/subscription/faq.html). Customized lists cost $5 for the first 200 records, then $0.05 per additional record. This implementation authorizes none of those actions. See the [current reassessment](states/UT-BUSINESS-SOURCE-REASSESSMENT-2026-10-03.md).

Only an operator-supplied closed package beneath `data/imports/utah-business-list/packages/` is accepted. Legacy packages may retain the original delivered workbook and separately contain three operator-derived JSONL exports. The validator pins the workbook and derived files by exact filenames, hashes, byte sizes, row counts, transformation declaration, and cross-sheet Entity ID references. Those legacy packages remain `operator-derived-jsonl` with `reproducible_extraction_verified: false`.

The separate `utah-business-list-workbook-replay@1.0.0` successor accepts an explicitly supplied `.xlsx` directly beneath `data/imports/utah-business-list/workbooks/` and emits the same closed package shape. Run `npm run utah-business-list:replay -- --workbook data/imports/utah-business-list/workbooks/<file>.xlsx --package-id <id> --observed-at <ISO instant> --updated-through <YYYY-MM-DD>`. It performs zero network activity; requires exactly the visible `BUSENTITY`, `BUSINFO`, and `PRINCIPAL` sheets, their exact published headers, contiguous rows and valid cross-sheet Entity ID references; and rejects formulas, hyperlinks, macros, external relationships, connections, embedded objects, extra sheets/fields, duplicate rows and oversized ZIP contents. IDs and postal values remain strings. ZIP5 and ZIP4 are separated only by the existing normalization boundary.

Replay blanks applicant names, unrestricted `BUSINFO.Information`, principal names and principal addresses before deterministic JSONL serialization. It independently replays the staged workbook and compares all three output hashes before writing `selection.json` last and atomically publishing the package. The legacy inspector then repeats the workbook-to-JSONL comparison before accepting `reproducible_extraction_verified: true`. This narrow claim establishes deterministic local equivalence only. It grants no source authenticity, purchase/account authority, use or redistribution rights, current-operation status, physical-site status, completeness, production admission, pointer change or national admission. Both workflows remain available and backward compatible.

The normalized result is provisional organization-level registration evidence from `BUSENTITY`. It excludes Applicant Name and does not emit `BUSINFO` or `PRINCIPAL`, because those sheets can contain officers, principals, partners, registered agents, and other natural-person information. Source address and status are explicitly administrative registration evidence, not proof of a physical site or current business operation. ZIP5 and ZIP4 remain separate. Deterministic replay alone does not make output admissible; independent original-byte authenticity and rights/admission decisions remain unresolved.

## Standalone offline app operation

`node scripts/run-utah-business-list-app.mjs --selection data/imports/utah-business-list/packages/<package-id>/selection.json` creates a UUID-scoped operation. The operation durably records its start before copying inputs, validates snapshot hashes, writes and verifies a local-review-only release, removes its temporary snapshot, and finishes with a terminal receipt. Failure and cooperative cancellation remove only the operation-owned snapshot and unpublished release. Package inputs are never changed.

`node scripts/verify-utah-business-list-app.mjs --receipt data/imports/utah-business-list/operations/<run-id>/receipt.json` independently replays the receipt, start hash, manifest, record artifact, counts, input bindings, and authority claims. The managed server and Data Operations UI can dispatch this same local worker through `ut-business-list` after an operator selects a package. Managed completion independently verifies its receipt. Neither route can purchase, create an account, access the source network, update a current pointer, or perform national admission. Every release preserves `source_native: false`, `source_authenticity_verified: false`, and `admission_eligible: false`; only packages produced and rechecked by the governed successor may preserve `reproducible_extraction_verified: true`. Enrollment alone proves no successful operation; the package and operation directories were empty during the October 3 reassessment.
