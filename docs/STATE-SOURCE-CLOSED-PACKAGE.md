# Closed state-source package preflight

`runner/state-source-closed-package.mjs` is a source-neutral, read-only preflight for operator-supplied state data. It deliberately does not acquire, normalize, publish, enroll, or admit a package to the broad organization layer. Passing this check is necessary evidence for a future source-specific workflow, never sufficient authority for one.

The package is closed to exactly six files: `manifest.json`, `authorization.json`, `source.json`, `schema.json`, `policy.json`, and `records.jsonl`. Every non-manifest file is byte- and SHA-256-bound by the manifest. The authorization binds the exact source, projection schema, policy, and state. A separately supplied, plain-data registry with exact status `closed` must pin that exact authorization receipt and all three declaration hashes for the same source and state. The verifier snapshots that registry before any asynchronous filesystem work, rejecting accessors, custom prototypes, cycles, sparse arrays, and non-JSON values. An empty registry therefore fails closed.

The projection must use distinct `zip5` and `zip4` fields. It may carry the address point as numeric `latitude` and `longitude`, but it cannot carry business geometry, polygons, bounding boxes, natural-person or registered-agent fields, direct contact fields, sensitive identifiers, filing documents, or free text. Every row must match the package state. Source-specific code must impose any stronger field meanings, identifier rules, status codebook, temporal semantics, address-role rules, licensing terms, and redistribution restrictions.

The containment root must itself be a canonical directory. The package path must resolve as a canonical child inside `datahub` (or the explicitly supplied test root); the root itself is not a package. Every artifact must be a canonical, single-link regular file. Directory identity and inventory are checked before and after bounded reads, and each file is checked for replacement while read. Record-byte, line-byte, and row-count ceilings are enforced before UTF-8 decoding or row parsing. Nonzero JSONL is LF-terminated with no blank rows. A zero-row package has one representation: `record_count: 0` and a zero-byte `records.jsonl` whose empty-file hash is pinned by the manifest.

The receipt and manifest must state zero network requests, no production pointer write, no broad-layer admission, no business geometry, and no joined ZIP value. The verifier returns those same negative claims plus `source_specific_authorization_satisfied: false`. It writes nothing and has no network path.

The generic registry pin proves only that these exact offline bytes were approved for this preflight. It cannot grant source access, satisfy licensing or privacy review, authorize acquisition, interpret status, permit redistribution, or substitute for a dedicated connector's authorization registry. The current 40-state authorization waves remain approval-only `HOLD` artifacts and do not populate this registry. Existing ACS, USPS, and Illinois workflows retain their own contracts. In particular, this preflight cannot convert an authorization-wave item, adjacent industry cohort, or operator-supplied file into broad statewide organization coverage. The next safe use is source-specific: create a reviewed registry entry only after resolving that source's outstanding gates, then have its dedicated connector consume the verified package and independently enforce its policy and schema.
