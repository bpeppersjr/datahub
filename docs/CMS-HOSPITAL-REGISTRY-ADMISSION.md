# Optional CMS hospital registry admission

This slice implements an optional typed registry artifact, not a new production release, new source acquisition, identity reconciliation, or nine-source reporting denominator. It uses the exact reviewed native CMS input through `loadCmsHospitalReportingInput`; source rows remain verbatim. Caller-selected fixture input cannot enter the native verifier.

`loadCmsHospitalRegistryInput(selectionPath,{signal})` accepts only the existing fixed CMS selection config path. The wrapper produces an exact source dependency and declaration with the native acquisition run/manifest hash, selected artifact bytes/hash, source dates, observation and acquisition-completion clock. Registry creation cannot predate source acquisition completion.

`buildNationalBusinessRegistry` gains only optional `cmsHospitalSelection` (default null). The separately versioned `cms-hospital-registry-input@1.0.0` envelope supports the explicitly existing reporting-capable base versions 2.12, 2.13, 2.14 and 2.15; base-version selection and unrelated TN/OH validations remain unchanged. Hospital data does not require an Ohio or Tennessee source. This is the same additive pattern used for MN credentials, not a broad future-version bypass. Older manifests without CMS remain supported unchanged.

New artifact: `reporting/cms-hospitals/directory.jsonl`, type `cms-hospital-directory-reporting-jsonl`, local-review-only. Dependency dataset: `cms-hospital-general-information`. Declaration: `cms_hospital_directory_reporting`. The only new count is `coverage.cms_hospital_directory_rows`. It does not change canonical organization/site/establishment counts, generic source-record totals or entity-resolution profiles. Identity status is **not-yet-reconciled**, not permanently unmatchable; later evidence-backed crosswalks are an explicit separate migration.

`verifyCmsHospitalRegistryExtension` rejects orphan declarations/artifacts/dependencies/counts and physically present undeclared typed output. Present declarations require full native input replay, exact dependency/declaration equality, exact selected source bytes/hash, complete ordered membership, chronology, separate count and policy. It replays source input again before returning. Pure envelope/membership helpers test structural contracts only and do not themselves establish native evidence.

The general registry verifier lazily imports the CMS dependency closure only when any reserved declaration, artifact type/path, dependency, count or actual typed file is present. This preserves historical copied-fixture import rosters without weakening orphan checks. Completion chronology is read from the independently verified acquisition manifest through the reporting helper, not duplicated as a time constant.

Focused tests cover optional absence, undeclared/missing/duplicate dependencies/artifacts, source/selection/hash/count drift, chronology, unsupported versions, policy/claim widening, exact row membership including alphanumeric IDs, sparse rows and pre-abort. No production registry build, production plan, source request, production pointer update or UI/CLI registration is executed by this slice. The inherited registry builder has no top-level AbortSignal option; this patch does not claim a new cancellation mechanism for that legacy full build. Direct wrapper/verifier APIs forward a supplied signal into native retained replay.

After root authorized a bounded integration fixture, the actual builder and full verifier were exercised against a tiny synthetic SNAP baseline plus the already verified CMS retained copy, entirely beneath isolated `data/tmp`. Both baseline and CMS-admitted registries used base 2.12 without Ohio; every legacy coverage count and all 100 resolution-profile artifact hashes/counts were identical. The admitted artifact conserved the exact 5,419-row selected hash, and a physically undeclared hospital file was rejected. A separate child-process import smoke denies every CMS module import while successfully verifying the legacy baseline, simulating old copied-fixture dependency rosters. Fixture output pointers are temporary test outputs, not production pointers, and are cleaned after the test. No production-scale registry build or source acquisition was run.

The tracked integration test is `runner/business-registry.test.mjs`, named `CMS hospital optional admission builds and verifies on base 2.12 without Ohio and preserves every legacy count/profile`. Run with `DATAHUB_TEST_CMS_RETAINED=1` and Node's `--test-name-pattern='CMS hospital optional admission builds'`; it requires the pinned retained CMS copy/config in APP_ROOT and performs no download. Every successful invocation leaves an aggregate-only proof in `data/tmp/cms-registry-integration-proof-<UUID>.json` and logs its path. Reviewed proof: `data/tmp/cms-registry-integration-proof-97635131-11dc-4b1b-9522-a7a478c05f07.json`, SHA-256 `1af92716aab625127da9fd6d075e25d7a66f28a0551e8f4877f9f1f8f2f29834`.
