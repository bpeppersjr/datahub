# Local refresh scheduler ownership recovery

The application owns `data/refresh-schedules/owner.lock` while its scheduler is running. Graceful shutdown releases that ownership. A restart may recover an abandoned lock only when its stored positive integer PID returns `ESRCH` from the local process probe. A live PID, permission error, unknown probe error, malformed owner, linked storage, or changed owner fails closed. PID reuse therefore prevents recovery rather than risking a live owner.

Every startup takes an exclusive `recovery.lock` before acquiring or inspecting `owner.lock` and retains it through initialization. Recovery rechecks the original owner and atomically archives it as `owner-dead-<recovery-id>.lock`. It then writes and syncs `recovery-<recovery-id>.json`, containing the prior PID, process-probe result, archive path, owner/state hashes, and a declaration that recovery changed no schedules and dispatched no operations. The receipt excludes the owner token. Normal exclusive ownership acquisition and stored-state validation follow. Recovery neither creates nor enables schedules; existing enabled schedules continue through the existing plan validation and occurrence reconciliation rules.

If initialization crashes, or recovery is interrupted after archiving but before its receipt completes, `recovery.lock` remains and subsequent startup refuses scheduling. Do not blindly remove it. Stop Collector using `stop-collector.bat`; confirm both the recorded recovery PID and any owner PID are dead, compare archived ownership and state hashes with any receipt, and inspect managed operation receipts for unresolved occurrences. Preserve the files and record the resolution before a reviewed manual repair. Unknown evidence requires investigation. This intentionally guarded exceptional path is not an automatic recovery promise.

Validation: `node --test runner/managed-refresh-scheduler.test.mjs` covers live ownership, concurrent stale-owner recovery, uncertain probes, malformed ownership/state, interrupted recovery, schedule preservation, dispatch identity, restart reconciliation, and graceful cleanup. Recovery never bypasses source-review gates.
