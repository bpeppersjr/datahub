# Broad-organization current-gap authorization program

It contains the 40 jurisdictions that still lack a production-ready general-business broad layer. Alaska and D.C. are deliberately absent because the current national matrix no longer reports them as gaps.

2. MD, ME, MI, MN, MS, ND, NJ, NV, SC, TN
3. VA, VT, WI, WV, AZ, IN, KS, LA, MO, MT
4. RI, SD, WY, AL, AR, GA, NE, NM, UT, WA

The management view adds a read-time broad-organization gate-readiness taxonomy v1.0.0 that exhaustively maps those exact 121 keys. It preserves each original program classification and derives a separate effective requirement: contract evidence, authenticated operator authorization, retained source-package evidence, reproducible execution/verification evidence, or national-admission decision. Four separate-acquisition-authorization gates (CA, ID, OH, NH), two national-admission gates (IL, MS), Illinois package/verification/freshness requirements, Mississippi source-authenticity/reproducible-extraction, and Utah deterministic workbook extraction/source-authenticity are explicitly non-document-only. Unknown keys fail closed.

This projection is bound to the deeply verified program manifest/artifact, its pinned backlog manifest/artifact, and the current verified assessment catalog ID/hash. It does not rewrite or republish any historical or current source artifact. All 371 items remain unresolved, row-bearing evidence is false, authority remains false, and the projection gives no readiness uplift. Documents may support contract-evidence review only; they cannot themselves authorize an operator, supply a retained package, prove reproducible execution, or make the national-admission decision.

The historical v1 release remains immutable and independently verifiable. It continues to represent its original 43-jurisdiction, 371-item, five-wave snapshot; its bytes, release identity, and backlog lineage are not rewritten. The older ten-jurisdiction authorization-packet release is also unchanged.

```powershell
npm run broad-org-authorization-program:build
npm run broad-org-authorization-program:verify
```

With no arguments, the scripts select the sole canonical v2 backlog or v2 program release. An exact historical or current manifest can still be verified by passing its path. Output is restricted to a child of canonical `APP_ROOT/data`, publication is manifest-last and content-addressed, and no `current.json` pointer is created.

This program is not acquisition approval. Reviewing a document can establish contract-evidence sufficiency only; it cannot authorize contact, access, payment, record acquisition, or production use.
