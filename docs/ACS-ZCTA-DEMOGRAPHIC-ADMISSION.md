# ACS ZCTA demographic admission prerequisites

This module is a fail-closed, read-only contract inspection. It cannot ingest source rows, create staging storage, publish a release, write a pointer, or enroll anything in production. The repository currently has no retained trusted official ACS group-metadata release, approved structured source receipt, or immutable governed ACS source release. Those are explicit blockers, not caller-supplied assertions.

The checksum-pinned network plan now identifies the current official source as the 2020–2024 ACS 5-year Detailed Tables, publicly released January 29, 2026. It bounds a future app-owned run to four official group-metadata requests and four all-ZCTA group-data requests on `api.census.gov`, serial execution, same-host redirects, and the B01001, B02001, B03002, and B04006 groups. The plan is reviewed but not authorized or executed: it performs zero network requests and changes no pointer or production enrollment. Its official evidence is the Census release schedule, 2024 ACS developer documentation, API dataset and geography catalogs, and Census ZIP/ZCTA explanation.

`runner/acs-zcta-demographic-network-response.mjs` implements the source-response boundary without making network calls. It validates the complete 756-column E/M/EA/MA roster across the four groups, accepts source column reordering by header identity, preserves zero-padded ZCTAs, raw negative sentinels and null annotations, rejects duplicate identities and numeric coercion, and reports cross-group missing ZCTAs instead of inventing cells. A complete source row conserves exactly 189 base variables. The reconciler does not replace the governed map roster, enroll production, write a pointer, or claim that acquisition occurred.

`runner/acs-zcta-demographic-network-spool.mjs` provides the app-owned transport boundary without exposing an executable network route. It streams one accepted JSON response at a time into an operation-specific staging directory, enforces an immutable destination and a 512 MiB per-group ceiling, computes SHA-256 while writing, checks cancellation and directory identity before atomic retention, and removes partial files on rejection. The plan caps all retained source responses at 1 GiB and requires 2 GiB free disk before a future run. These are disk-storage bounds, not a RAM allocation or permission to execute the plan.

Future reconciliation must preserve the ACS-returned ZCTA roster and the governed map roster separately, reporting source-only and map-only identifiers rather than silently forcing equality. A private, unique, or PO-box ZIP without a Census ZCTA is `not-applicable-no-census-zcta-demographic-estimate`; it does not block the map. ZCTA remains statistical geography, ZIP+4 remains separate, ACS values remain estimates with margins of error and annotations, and demographic GDP allocation remains unauthorized.

An app-owned offline admission foundation is also implemented, but no real package is registered or admitted. The protected managed-operation endpoint `POST /api/data-operations/source-admissions` accepts only `{ "packageDirectory": "data/imports/<directory>" }`. It never accepts a URL. The directory must have the closed inventory `manifest.json`, `metadata.json`, `authorization.json`, and `data.jsonl`; input is copied with byte ceilings and identity checks into the operation directory before validation. `data.jsonl` must be fatal UTF-8 with exactly one non-empty JSON object per LF-terminated line; CRLF and a missing final LF are rejected. Admission requires an exact 33,791-ZCTA roster, all 189 base variables with raw E/M/EA/MA values, exact official-metadata variable mappings and universes, and an authorization that explicitly denies network acquisition, production enrollment, and current-pointer changes. Successful output retains the package manifest and is independently replayed against the pinned source policy, metadata registry, authorization registry, and geography in a manifest-last immutable release under `data/acs-zcta-demographics/releases/`; it remains local-review-only and pointer-free.

The four tables remain separate evidence. `B01001` is sex by age, `B02001` is race, `B03002` is race by Hispanic/Latino origin, and `B04006` is ancestry. Admission does not construct a race × ancestry × sex × age cube, reinterpret ancestry as exclusive lineage, emit percentages, or represent a ZCTA as a USPS delivery ZIP.

The offline candidate-row validator is also fail-closed. It requires one exact five-digit ZCTA and the complete 189-cell roster across the four reserved groups. Every cell must contain exactly raw `E`, `M`, `EA`, and `MA` values; numeric values remain strings, negative sentinels are preserved verbatim, annotations remain distinct, and missing values are represented only as `null`. Missing, extra, coerced, blank, or control-character values are rejected. Validation creates no receipt, staging directory, release, pointer, or authorization state.

`config/connectors/acs-zcta-demographic-admission.json` registers this narrow capability with Co*Tive's connector catalog. It has no allowed hosts or secrets, declares zero network requests, and is explicitly production-disabled. Its local package intake, validation, immutable local-review publication, verification, and managed-operation finalization are implemented; network acquisition, a current pointer, production enrollment, and downstream readiness promotion are not.

The contract reserves four ACS 5-year detailed-table groups: `B01001` sex by age (cells 001–049), `B02001` race (001–010), `B03002` race by Hispanic or Latino origin (001–021), and `B04006` ancestry (001–109). Every eventual cell must preserve the estimate (`E`), margin of error (`M`), estimate annotation (`EA`), and margin-of-error annotation (`MA`). Raw negative sentinels and annotations must be preserved, but their meanings remain explicitly unresolved until trusted official metadata is retained. No sentinel meaning, percentage, or lineage reinterpretation is invented.

Inspection independently replays the checksum-pinned policy, empty official-metadata registry, empty authorization registry, geography manifest, and every row of the governed 2020 Census ZCTA JSONL through a descriptor-bound stream. It enforces the absolute byte and line ceilings, exact checksum, exactly 33,791 unique five-digit ZCTA identities, and required geography/population/housing shape. Registry entries cannot imply availability until a future strict closed-schema validator exists; any entries are reported as unsupported or untrusted. ZCTAs remain Census statistical geography rather than USPS ZIP delivery boundaries.

Run prerequisite inspection with:

```powershell
node scripts/build-acs-zcta-demographic-admission.mjs inspect
```

The inspection CLI rejects publish, declaration, unknown, duplicate, and missing flags. Offline local-review admission is available only through the authenticated managed-operation endpoint described above; the internal worker CLI is not an operator interface. The pinned registries are intentionally empty, so no real package can currently pass admission. Populating them requires a separately reviewed authorization change that retains exact official Census group metadata (including labels, concepts, universes, and variable/annotation rosters) and an approved structured receipt. No sample or self-asserted metadata may unlock publication.
