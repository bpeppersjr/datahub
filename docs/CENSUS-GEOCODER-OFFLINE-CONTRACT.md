# Offline Census geocoder batch contract

This module performs in-memory planning and synthetic response conformance only. It sends no HTTP requests, writes no artifacts, reads no retained CMS records and provides no native readiness or outbound-disclosure approval. Source and benchmark hashes are caller-supplied linkage, explicitly not replayed evidence. The existing CMS source release and native geocodes are not changed.

`planCensusGeocoderBatch(rows, {source, benchmark, signal?})` accepts a closed source descriptor and an explicitly selected reviewed public benchmark ID/name plus catalog hash/observation: Current (`4`, `Public_AR_Current`), ACS2025 (`8`, `Public_AR_ACS2025`) or Census2020 (`2020`, `Public_AR_Census2020`). No default is used and LUCA is excluded. ACS2025 is the newest named public edition observed by the research lane and is used in the primary fixtures; Census2020 is available for an explicitly chosen historical alignment, not forced on the current-business objective. Neither a fixed edition name nor Current pins immutable underlying address-range data. A future lifecycle must verify actual catalog bytes, chosen ID/name and policy before/after processing; this offline helper does not claim catalog authenticity or content freshness.

Each source row has a private source-record ID and original street/city/municipio/state/ZIP5/ZIP4/urbanization fields, with city and municipio distinct nullable values. The CSV contains only a newly generated opaque ID and address components. Source IDs/names/phones never enter the upload. Repeated addresses receive distinct opaque IDs. ZIP4 stays separate in the private mapping and is not submitted. Per the [official batch API layout](https://geocoding.geo.census.gov/geocoder/Geocoding_Services_API.html), Puerto Rico without urbanization uses five fields ID/street/city/state/ZIP; with urbanization it uses six fields ID/street/municipio/state/ZIP/urbanization. City is never substituted for municipio. Urbanization without a nonblank municipio is explicitly ineligible. Missing street, unsupported/missing state and non-PR urbanization layout also remain ineligible, not silently repaired. Blank optional fields preserve their columns; unknown urbanization is never invented. Current candidate eligibility supports the 50 states/DC/PR, not other territories without a reviewed layout.

`inspectCensusGeocoderBatchResponse(plan, bytes, {signal?})` requires a genuine immutable plan. It links every returned opaque ID to its original source row, preserves returned input-address echo and raw status/type, and rejects extra/missing/duplicate IDs and unknown status. It reorders accepted results to planned order; input-address echo is retained for audit, not falsely claimed to exactly equal the provider's formatting of submitted components. All planned rows reconcile to ineligible, matched, unmatched or tie; invalid/unknown rows fail the whole response rather than turning into points.

## Candidate wire-layout boundary

Documentation reviewed by the research lane establishes field meanings, not a verified native status-specific CSV fixture. This offline validator tests an explicit candidate layout: matched rows have eight fields (ID, input-address echo, Match, Exact/Non_Exact, matched address, quoted longitude/latitude pair, TIGER line ID, side L/R); No_Match/Tie have three fields plus zero to five empty trailing fields. Headerless CSV is expected. These arity/padding assumptions remain unverified against native response bytes and must be resolved before runnable transport adoption. Tests demonstrate this candidate's conformance, not that every official response variant is accepted. No native wire-schema claim is set true.

Coordinates retain provider NAD83, unknown realization and longitude-X/latitude-Y order. They are approximate address-range interpolation, not rooftop/structure or active-business proof. Numeric ranges detect some axis errors, but cannot detect a swapped pair when both numbers fall within both valid ranges. No silent EPSG:4326/WGS84 conversion, confidence percentage, county/ZCTA assignment or ZIP-centroid fallback exists. Status No_Match/Tie produces null coordinates. Matching never makes source addresses or operating status verified.

Bounds: 10,000 planned rows, 5,000,000 CSV upload bytes, 20 MiB response, 65,536-character CSV record cap, fatal UTF8 and cooperative signal/yield checks. No timer, network, lease, retry or publication lifecycle is implemented; a caller may pass a deadline signal. Tests exercise actual short timer expiry during yielded planning, not HTTP deadline/cleanup behavior. A future application lifecycle still needs provider-wide arbitration, bounded fetch/read/cleanup, durable private mapping/request intents, uncertain-submission recovery, immutable manifest-last publication and independent replay.

The offline result has response bytes/hash but no actual response-observation timestamp. A future native receipt must capture geocoder response observation separately from benchmark-catalog observation and CMS source observation. Never substitute one clock for another. Eleven focused tests and ESLint passed after the reviewed Puerto Rico layout and explicit public-benchmark corrections; no native response or transport proof was performed.

Policy `config/source-policies/census-geocoder-public-addresses.json` keeps mapping/raw response internal and proposed derived output local-review-only. General Census privacy documentation is not a batch-retention guarantee. This slice neither infers outbound disclosure authority from CMS reuse nor creates secret-key or artificial manual-approval requirements. Native operation requires the separately reviewed source-specific disclosure/retention policy and lifecycle. Future state consumers must reuse a single geocoded cohort; this is not a proposal for 50 duplicate uploads.

Official references and research limits are recorded in the parallel source note `docs/CENSUS-GEOCODER-HOSPITAL-FEASIBILITY-2026-09-12.md` (Maine worktree): API documentation, May 2026 guide, legacy NAD83 FAQ and current Geocoder FAQ. This implementation made no additional source requests.
