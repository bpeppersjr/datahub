# Collection cancellation and publication

Co*Tive owns collection worker execution. Cancellation is a request to stop, not a rollback transaction and not proof that no data was published.

The shared local defaults in `runner/collection-cancellation.mjs` give industry source workers 60 seconds after IPC cancellation before requesting forced termination. Managed collection supervisors receive 75 seconds, allowing the inner grace plus time to close streams, persist receipts and release source reservations. Managed exports retain their existing 15-second grace. These are fixed runtime settings, not user-supplied HTTP or job options; provider rate limits and parallelism are unchanged.

Delaware's two non-cancellable publication rename retry schedules total at most 44,700 milliseconds of scheduled waiting. The collection grace is longer than that schedule. This does not bound OS filesystem calls, event-loop stalls, disk failure, cleanup duration or process death, and it does not promise automatic repair of a forced termination. Publication-incomplete errors and retained evidence still require inspection. This migration is not Delaware source enrollment or authorization to download again.

For compatibility, a run observing cancellation retains its `cancelled`/`CANCELLED` control status. Source task receipts additionally preserve the observed exit code, signal, whether forced termination was requested, and `cancellation.child_exit_succeeded`. An exit-zero child may have completed publication; a nonzero child may have partially published. Both carry `output_state: inspection-required`. The managed result and task snapshots expose this ambiguity, and the operator warning explicitly requires inspecting receipts and retained artifacts before retrying. The flag records a termination request, not confirmation that the operating system terminated the process. Unknown executor outcomes retain a null termination flag.

The regression uses a real managed executor, a fixture industry supervisor running the actual industry executor, and a synthetic Delaware build. Cancellation is sent after the committed-pointer marker; the source then finishes a bounded 16-second postcommit step, longer than both former grace periods. The published release is independently verified, and the publication lock and child processes must be gone. The fixture supervisor reports completion with exit zero so the test can inspect its receipt; the ordinary industry CLI still exits nonzero for a cancelled control outcome. This is not a production operation or a download receipt. Separate managed-service tests cover successful/nonzero child exits under cancellation, durable ambiguity metadata and unchanged export timeout selection.

Rollback restores the prior shared timing/wiring and receipt annotations only after checking active operations. Do not remove operation history, source locks, staging or immutable releases. Historical receipts without the additive cancellation fields remain readable; they do not acquire new guarantees retroactively.

TypeScript checking passed; the production dependency audit reported zero vulnerabilities. All 82 pending production code/config pins stayed unchanged.
