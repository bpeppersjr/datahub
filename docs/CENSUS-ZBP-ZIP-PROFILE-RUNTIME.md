# Bounded Census ZIP industry profile runtime

The existing authenticated ZIP-inspector GET now includes `census_zbp_industry_profile`, with independent `census-zbp-zip-industry-view@1.0.0` identity, source/index/registration bindings and restrictive claims. This is additive: existing ordinary counts and temporal qualification remain unchanged. It is ZIP-wide and not mapped to or filtered by the selected app evidence category.

The reader accepts only the tracked `config/datasets/census-zbp-zip-profile-index.json` registration. It verifies the closed registration shape, exact manifest/inventory/claims, current selected ZBP source, geography and source policy, and every occurrence of the selected registry's ZBP dependency. It checks the registry/geography IDs and hashes against the ordinary inspector catalog. Only one index bucket and one positional derivative profile range are read; no source decompression, fallback scan, build, acquisition or publication occurs. Bounded metadata hashes and relevant file identities are rechecked after auxiliaries. Missing/tampered/drifting data yields explicit nested unavailable, not a zero or fabricated absence; cancellation propagates.

All exact industry rows, size counts, suppression codes, nulls and zeroes remain intact. The original profile and source coverage semantics remain nested. Publisher place labels do not establish governed geography. The response is historical reference-year2023 employer-establishment context, not named businesses, current operation, GDP, GDP weights or all-business completeness. No NAICS parent/child rows are added. An absent ZIP union member and an existing denominator-only profile with no industry rows remain distinct.

ZIP Economy Overview consumes this same response without another browser request. It displays the exact total publication code `------` only when present, never a sum of hierarchy rows; a collapsible exact-code table includes all nine size classes and source flags, publisher labels, keyboard-focusable scrolling and inherited text size. Retry uses the existing inspector request and stale-response cancellation.

Runtime profile envelopes are capped at1.5MB, beneath the unchanged2MB combined inspector response ceiling; an oversized future profile is withheld as unavailable rather than truncated. The native opt-in focused test (`DATAHUB_TEST_ZBP_ZIP_PROFILE=1`) locates the largest installed profile using only ten small index buckets, then exercises the composed ordinary/qualification/USPS/ZBP response through the existing HTTP size guard. It does not replay source partitions or run the full app. Legacy source-specific auxiliary loaders retain their existing cancellation limitation and are not included in this bounded-reader size measurement.

Dedicated implementation/testing uses supported Astra fallback. No index/registration contract or production pointer is modified. Full repository and live desktop verification remain integrator-controlled after review.
