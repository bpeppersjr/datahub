# Stop local development services cleanly

For the local browser/runner pair launched with `npm run dev:web`, run `stop-collector.bat` from Windows, or `node scripts/stop-dev-web.mjs`. This is the development launcher stop command, not an Electron quit command or a Windows service installer. It does not target independently launched production reconciliation controllers.

The launcher stores a unique session receipt beneath `data/dev-runtime/<UUID>/`. The stop command discovers exactly one live launcher or requires an explicit `--run-id UUID` when selection is ambiguous. It writes a matching local stop request. The launcher sends its runner the existing cooperative IPC shutdown message and stops its UI child; it records `STOPPED` only after its direct children exit. No API credentials are written to disk. The control files use the same local filesystem trust boundary as application runtime data and do not expose a network endpoint.

An explicit file-request stop has no launcher force-kill fallback for the IPC runner. The command waits up to 45 seconds for confirmation; timeout is an unresolved stop, not proof of failure or permission to delete a lock. Investigate the runner's process and durable operation receipts before further action. Managed-operation shutdown retains its own existing cooperative cancellation and escalation rules. Active collections may be cancelled during app shutdown; pause schedules or let work finish first when continuation is desired.

Hard terminal termination, OS crashes, and legacy signal/failure paths remain distinct: the launcher's latter paths retain a 30-second fallback rather than its former five-second limit. This command does not automatically reclaim any old scheduler/source lock and does not recover a session killed before receipt finalization. A stale PID never causes this command to kill another process; a stop request is consumed only by its matching launcher session.

Three control tests cover one-time handling, terminal receipt, ambiguous/dead selection, and mismatched identity. The real supervisor test uses the file request and checks both child-service closure and removal of its fixture scheduler owner lock. Windows transient rename collisions are retried while publishing the same receipt. No business data or scheduled acquisitions are created by these tests.

Rollback: let development services stop cleanly before reverting the launcher integration. Preserve `data/dev-runtime` receipts and unresolved scheduler/source ownership for inspection; removing the command does not require deleting runtime evidence.

Verification: all 502 repository tests, lint, web/desktop builds, desktop smoke, TypeScript, and a zero-vulnerability production audit passed. The actual newly launched local app was stopped with `node scripts/stop-dev-web.mjs`; the command confirmed completion, its scheduler owner lock was absent, and the separate production controller/registry worker PIDs 5768/12784 remained alive. The app was then restored. The legacy launcher stopped before this integration left its old empty scheduler lock, which was preserved as `owner-stopped-24140-20260907.lock` after exact process/state inspection; the new stop test required no such recovery.
